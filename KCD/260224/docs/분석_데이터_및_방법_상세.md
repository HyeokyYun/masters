# 260223 분석 데이터·범위·방법 상세 (교수님 미팅용)

**목적**: 본 분석이 **어떤 데이터를, 어디서 어디까지, 어떤 방법·형식**으로 수행되는지 세세히 정리하여 논문 디펜스 및 미팅에서 명확히 설명할 수 있도록 함.  
**저장 위치**: `260223/docs/분석_데이터_및_방법_상세.md`  
**최종 갱신**: 파이프라인 코드·설정 기준.

## 0. 한눈에 보는 범위·형식 (미팅용 요약)

| 구분 | 범위·형식 |
|------|------------|
| **분석 단위** | 업장(public_id) 단위. Step 3b만 주별(업장×주차) 후 집계. |
| **Step 1 입력** | 260204 `data_features_clean.parquet` (33,514행×34열) 또는 basic_data CSV. |

| **Step 2 출력** | 33,864행. final_code, inflection_week, cluster(K6), slope_P1/P2 등. |

| **Step 3b 대상** | DUY 934 + DDZ 3,772업장. t=0 전후 12주. 지표: 신규고객비율 우선, 없으면 4주 매출성장률. |

## 2. 데이터 출처·범위·형식

### 2.1 Step 1 입력 데이터 (마스터 테이블의 근원)

| 구분 | 내용 |
|------|------|
| **우선 사용** | `26-1/260204/outputs/data_features_clean.parquet` |
| **대체** | `26-1/basic_data/store_features_for_analysis.csv` (parquet 없을 때) |
| **형식** | Parquet: 컬럼 34개, **행 수**: 33,514 (실행 로그 기준) |
| **단위** | **1행 = 1업장(public_id)**. 시계열이 아닌 **업장별 집계(피처)** 테이블. |
| **시간 범위** | 원본은 260204/260121 파이프라인에서 정의한 주차 구간(예: day_after1 기준 주별 집계 후 업장별 요약). 260223에서는 **기간을 추가로 자르지 않음** — 260204에서 나온 전체 구간 그대로 사용. |
| **업장 범위** | 260204 `data_features_clean`에 포함된 모든 업장. 결측 제거 후 **33,514업장** 유지. |

**Step 1에서 사용하는 컬럼 (있으면 유지)**  
- **수치**: `public_id`, `growth_rate`, `new_customer_ratio`, `cv_sales_card`, `business_age_months`, `business_density`, `business_square_size`, `avg_sales_card`, `std_sales_card`, `trend_slope`, `total_weeks`, `weekend_ratio`, `avg_customer`, `card_ratio`, `delivery_ratio`, `max_sales`, `min_sales`, `max_min_ratio`, `dong_store_count`, `dong_avg_sales`, `sigungu_store_count`, `sigungu_avg_sales`  
- **범주**: `sigungu`, `depth_1`, `depth_2`, `depth_3`, `dong`, `cluster`(있으면 유지, Step 2에서 K6로 덮어쓸 수 있음)

**Step 1 전처리 규칙**  
- **결측 제거**: `growth_rate`, `new_customer_ratio`, `cv_sales_card`, `business_age_months` 중 하나라도 결측이면 해당 행 제거. (실행 시 33,514→33,514이면 결측 없음.)  
- **이상치 완화**: `growth_rate`, `cv_sales_card`를 상·하위 1%로 **Winsorize** (1%, 99% 분위수로 클리핑).  
- **이진 변수 생성**: `growth_type` = 1 (성장) if `growth_rate >= 1`, else 0 (쇠퇴).  
- **출력 형식**: Parquet + CSV, 인코딩 UTF-8-sig.

**Step 1 출력**  
- **경로**: `260223/outputs/tables/df_base_features.parquet`, `df_base_features.csv`  
- **행 수**: 33,514  
- **실제 실행 결과**: growth_type 1=5,235, 0=28,279.

---

### 2.2 Step 2 입력 데이터 (UDX·변곡점·클러스터)

| 구분 | 내용 |
|------|------|
| **핵심 입력** | `26-1/260204_gem/outputs/tables/final_code_by_store_260121_outlier_removal.csv` |
| **행 수** | 33,864 (업장당 1행) |
| **키** | `public_id` (업장 ID) |

**포함 컬럼 예시**: `public_id`, `n_weeks`, `inflection_week`, `P1_label`, `P2_label`, `slope_P1`, `slope_P2`, `used_fallback`, `Pattern_label`, `final_code`, `cluster` 등.

**추가 병합**  
1. **K-Shape K6 클러스터**: `26-1/260204/outputs/tables/store_cluster_labels_K6.parquet`  
   - 컬럼: `public_id`, `cluster`.  
   - `final_code`의 `cluster` 컬럼을 K6 결과로 **덮어씀** (논문 통일).  
2. **변곡점 추가 수치**: `26-1/260204_gem/outputs/tables/inflection_p1p2_labels.csv`  
   - `public_id` 외에 `final_code`에 없는 컬럼만 병합 (예: `P1_slope`, `P2_slope`).

**Step 2 출력**  
- **경로**: `260223/outputs/tables/df_udx_labels.parquet`, `df_udx_labels.csv`  
- **행 수**: 33,864  
- **용도**: Step 3a·3b·4에서 `public_id` 기준으로 base와 merge.

---

### 2.3 Step 3a 회귀 분석 — 사용 데이터 범위

- **입력**: `df_base_features.parquet` + `df_udx_labels.parquet` (left merge on `public_id`).  
- **분석 대상**: merge 후 **Y·주요 X 결측 제거한 행만** 사용.  
  - Y: `growth_type`(이진), `growth_rate`(연속).  
  - 주요 X: `new_customer_ratio`, `cv_sales_card` (config의 `main_x`).  
- **실제 분석 샘플 수**: **33,514** (growth_type 1=5,235, 0=28,279).  
- **고정효과**: Model 3에서 `sigungu`, `depth_2` 더미 포함 (drop_first).

---

### 2.4 Step 3b Event Study — 사용 데이터 범위

- **UDX**: `df_udx_labels`에서 **final_code가 DUY 또는 DDZ인 업장만** 사용.  
  - **DUY**: 턴어라운드(성장 전환), **DDZ**: 쇠퇴.  
  - 로그 기준: DUY=934, DDZ=3,772, 합계 4,706업장.  
- **주별 데이터**:  
  - **파일**: `26-1/original_data/weekly_processed.parquet` (없으면 `weekly.parquet`).  
  - **형식**: 행 = 업장×주차. 로그 기준 약 5,686,549행, 55,310업장.  
  - **시간 컬럼**: config `time_col_week` (기본 `day_after1`).  
  - **지표**:  
    - **1순위**: 주별 `new_customer_ratio` (컬럼 있으면 그대로 사용).  
    - **2순위**: `customer_new`/`customer` 있으면 주별 `new_customer_ratio = customer_new / customer` 계산.  
    - **현재 환경**: 위 두 가지가 없어 **대리 지표** 사용 — **4주 전 대비 매출 성장률** `sales_growth_4w` (매출 컬럼: config `sales_col`, 기본 `sales_card`).  
- **이벤트 시간**: 각 업장의 **변곡점 주차(inflection_week)** 를 **t=0**으로 하고, **전 12주 ~ 후 12주** (`event_time` ∈ [-12, 12]).  
- **집계**: (event_time, final_code)별로 지표의 **평균·표준편차·관측 수·표준오차** 계산 → `event_study_means.csv`.  
- **그래프**: DUY vs DDZ 두 시리즈, t=0 수직선, 95% 구간(mean ± 1.96×se) 표시.  
- **출력**: `260223/outputs/figures/event_study_plots.png`, `260223/outputs/tables/event_study_means.csv`.

---

### 2.5 Step 4 Ablation — 사용 데이터 범위

- **입력**: `df_base_features.parquet` + `df_udx_labels.parquet` (merge on `public_id`).  
- **결측**: base 수치 피처 + `growth_type` 결측 제거.  
- **학습/테스트**: **stratified split**, test_ratio=0.2, random_state=42.  
  - 로그 기준: Train 26,811, Test 6,703.  
- **피처 개수**: Base only 약 54개, Full(base+UDX+변곡점) **69개** (실행 환경에 따라 더미 개수로 인해 달라질 수 있음).  
- **목적**: 미래 예측이 아니라 **UDX·변곡점 피처의 설명력(Feature Importance)** 증명용 Ablation.

## 3. 분석 방법 상세

### 3.1 Step 1 — 전처리

| 항목 | 내용 |
|------|------|
| **방법** | 260204 정제 parquet(또는 basic_data CSV) 로드 → 필요 컬럼만 선택 → 핵심 수치 결측 제거 → Winsorize → growth_type 이진 생성 → 저장 |
| **범위** | 위 2.1의 행/열 범위. 기간·지역 추가 필터 없음. |
| **형식** | Parquet, CSV (UTF-8-sig). |

---

### 3.2 Step 2 — UDX 라벨 통합

| 항목 | 내용 |
|------|------|
| **방법** | final_code CSV 로드 → K6 parquet로 cluster 덮어쓰기 → inflection CSV에서 추가 컬럼 merge → 저장 |
| **범위** | final_code에 있는 전체 업장(33,864). |
| **형식** | Parquet, CSV (UTF-8-sig). |

---

### 3.3 Step 3a — 계량경제 회귀

| 항목 | 내용 |
|------|------|
| **종속 변수** | **Logit**: `growth_type` (1=성장, 0=쇠퇴). **OLS**: `growth_rate` (연속). |
| **Model 1** | 설명변수: `new_customer_ratio`, `cv_sales_card` (+ 상수). |
| **Model 2** | Model 1 + 통제: `business_age_months`, `business_density`, `business_square_size`. |
| **Model 3** | Model 2 + 고정효과: `sigungu`, `depth_2` (더미, drop_first). |
| **추정** | statsmodels 있으면 OLS/Logit; 없으면 numpy OLS + sklearn LogisticRegression (p-value는 statsmodels 설치 시에만). |
| **출력** | `regression_tables_ols.csv`, `regression_tables_logit.csv` (long). `regression_ols_wide_coef.csv`, `regression_ols_wide_pvalue.csv`, `regression_logit_wide_coef.csv`, `regression_logit_wide_pvalue.csv` (variable×model). |

---

### 3.4 Step 3b — Event Study

| 항목 | 내용 |
|------|------|
| **방법** | 변곡점(inflection_week)을 t=0으로 정렬한 **event_time** 생성 → t ∈ [-12, 12]만 유지 → (event_time, final_code)별 평균·표준오차 계산 → DUY vs DDZ 시계열 플롯. |
| **지표** | **신규 고객 비율**(주별 new_customer_ratio 또는 customer_new/customer) 우선; 없으면 **4주 매출 성장률(sales_growth_4w)** 대리 사용. |
| **범위** | DUY·DDZ 업장만, 전후 12주. |
| **출력** | `event_study_plots.png`, `event_study_means.csv`. |

---

### 3.5 Step 4 — Ablation (설명력 증명)

| 항목 | 내용 |
|------|------|
| **설계** | **base_only**: base 수치 + sigungu/depth_2 더미 (UDX·변곡점·final_code 제외). **base_udx_inflection**: base + cluster, slope_P1, slope_P2, inflection_week + final_code 더미(UDX_Code). |
| **모델** | RandomForest, XGBoost(설치 시), LightGBM(설치 시). 각각 base_only·full 둘 다 학습·평가. |
| **평가** | Accuracy, F1 (test set). |
| **시각화** | SHAP 설치 시: TreeExplainer로 SHAP Summary Plot (beeswarm + bar), 모델별 저장. 항상: full 모델의 **tree feature_importances_** 막대 그래프 저장. |
| **출력** | `prediction_metrics.csv`, `shap_summary_*.png`, `shap_summary_plot.png`, `feature_importance_*_full.png`. |
